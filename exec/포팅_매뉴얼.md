## 빠른 실행 (클론 → 실행)

### 사전 준비

JDK 17 · Node 24.18.0 · Docker Desktop. 포트 `3306` · `8080` · `5173` 가 비어 있어야 한다.

### 1) 클론 & DB

```bash
git clone https://lab.ssafy.com/s15-webmobile1-sub1/S15P11A206.git
cd S15P11A206
docker compose up -d mysql
```

### 2) 백엔드

```bash
cd backend
DB_PASSWORD=root SPRING_PROFILES_ACTIVE=local ./gradlew bootRun
```

첫 기동에서 Flyway가 `V1`~`V29` 를 적용한다. `Started BackendApplication` 이 뜨면 성공이다.

외부 서비스 기능까지 보려면 키를 함께 준다(없어도 나머지는 정상 동작한다).

```bash
DB_PASSWORD=root SPRING_PROFILES_ACTIVE=local \
  KAKAO_REST_API_KEY=<발급받은 카카오 REST API 키> GMS_KEY=<발급받은 GMS 키> ./gradlew bootRun
```

### 3) 프론트엔드

새 터미널에서:

```bash
cd frontend
nvm use            # .nvmrc = 24.18.0
npm ci
cp .env.example .env
```

`.env` 에서 **두 줄만** 고친다. 나머지는 그대로 둔다.

```
VITE_API_BASE_URL=
VITE_DEV_API_TARGET=http://localhost:8080
```

```bash
npm run dev
```

### 4) 접속 확인

| 대상 | 주소 |
| --- | --- |
| 관광객 화면 | http://localhost:5173/user/splash |
| 상담자 콘솔 | http://localhost:5173/counselor |
| API 문서 (Swagger) | http://localhost:8080/swagger-ui/index.html |
| 헬스체크 | http://localhost:8080/api/health |

**관리자**는 시드 계정으로 바로 로그인된다 — `admin` / `AdminBootstrap!2026`.

**상담자 계정은 직접 만든다.** 회원가입 API가 공개돼 있다.

```bash
curl -X POST http://localhost:8080/api/auth/signup \
  -H 'Content-Type: application/json' \
  -d '{"loginId":"tester1","password":"Test1234!","name":"평가자","stationId":1}'
```

아이디는 영문·숫자·밑줄 4~20자, 비밀번호는 영문·숫자·특수문자 포함 8~20자다.
`stationId` 는 시드에 들어 있는 역삼역이 `1` 이다. 만든 계정으로 `/counselor` 에서 로그인한다.

> 📱 **카메라 위치 인식(WebXR)은 안드로이드 크롬 실기기에서만 동작한다.** 데스크톱 브라우저에서는
> "지도만 보고 이동하기" 로 넘어가 실내 지도·경로 안내를 확인할 수 있다. AI 측위 서버를 띄우지
> 않아도 이 경로는 정상 동작한다.

### 전체 검증 (선택)

```bash
cd frontend && npm run check    # typecheck + lint + FSD + prettier + test + build
cd backend  && ./gradlew test
```

## 2. 빌드 시 사용되는 환경 변수

### 2.1 Backend

`application.yaml` 이 `${VAR:기본값}` 으로 읽는다. **대부분 기본값이 있어 생략 가능**하고,
실제로 손대야 하는 것은 아래 셋뿐이다.

| 변수 | 필수 | 기본값 | 용도 |
| --- | --- | --- | --- |
| `DB_PASSWORD` | ✅ | `1234` | DB 비밀번호. compose는 `root` 라 **반드시 덮어써야 한다** |
| `KAKAO_REST_API_KEY` | ⬜ | (빈 값) | 역·목적지 검색, 도보 경로 |
| `GMS_KEY` | ⬜ | `dummy-key` | 상담 요약·자막 번역·음성 전사 |

자주 바꾸는 나머지:

| 변수 | 기본값 | 용도 |
| --- | --- | --- |
| `DB_USERNAME` | `root` | DB 계정 |
| `SPRING_PROFILES_ACTIVE` | (지정 필요) | 로컬은 `local` |
| `JWT_SECRET` | `change-this-to-...-local-only` | JWT 서명 키 (§3 참조) |
| `APP_CORS_ALLOWED_ORIGINS` | `localhost:5173~5175`, 배포 도메인 | CORS 허용 오리진 |
| `AI_LOCALIZATION_BASE_URL` | `http://localhost:8000` | AI 측위 서버 |
| `AI_LOCALIZATION_INTERNAL_TOKEN` | (빈 값) | AI 서버 `AI_INTERNAL_TOKEN` 과 같은 값이어야 한다 |
| `SIGNALING_WEBSOCKET_MAX_TEXT_MESSAGE_BUFFER_SIZE` | `1048576` | SDP 잘림 방지 (§3 참조) |
| `WEBRTC_TURN_URLS` / `_USERNAME` / `_CREDENTIAL` | (빈 값) | TURN 자격 증명 |

전체 목록은 `backend/src/main/resources/application.yaml` 에서 `${` 로 검색하면 나온다.

### 2.2 Frontend

Vite는 **빌드 시점에 값을 번들에 박아 넣는다.** 런타임 변경 불가.

| 변수 | 로컬 실행 | 운영 빌드 (Jenkins) | 용도 |
| --- | --- | --- | --- |
| `VITE_API_BASE_URL` | **빈 값** | **빈 값** | 백엔드 주소. 비우면 상대 경로로 부르고 프록시가 넘겨준다 |
| `VITE_DEV_API_TARGET` | `http://localhost:8080` | (미사용) | 개발 서버 프록시 대상. 빌드 산출물에 안 들어간다 |
| `VITE_WS_BASE_URL` | (그대로 둠) | `wss://i15a206.p.ssafy.io` | 시그널링 WS |
| `VITE_APP_ENV` | `development` | `production` | 실행 환경 |
| `VITE_NAVER_MAP_BASE_URL` · `VITE_STUN_URL` · `VITE_TURN_*` | (빈 값) | (빈 값) | 선택 항목 |

> ⚠️ **`VITE_API_BASE_URL` 줄을 지우면 안 된다.** 스키마 기본값이 빈 문자열이 아니라 배포
> 주소(`https://i15a206.p.ssafy.io`)라, 생략하면 로컬 백엔드가 아니라 배포 서버를 호출한다.
> **빈 값으로 남겨 두는 것**이 로컬 실행 설정이다.
>
> 이때 시그널링 WS 주소는 페이지 오리진에서 자동으로 유도되므로 `VITE_WS_BASE_URL` 은
> 건드리지 않아도 된다.

검증은 `frontend/src/shared/config/env.ts` 의 zod 스키마가 수행한다.

### 2.3 AI 서버 (선택)

`ai/ec2-cpu.env.example` 을 복사해 쓴다. 핵심은 `AI_INTERNAL_TOKEN` 이며 백엔드
`AI_LOCALIZATION_INTERNAL_TOKEN` 과 **같은 값**이어야 한다.

## 3. 배포 시 특이사항

### 3.1 배포 구성

운영은 EC2 + Nginx + systemd 구성이며 Jenkins가 GitLab push를 받아 자동 배포한다.

| 항목 | 값 |
| --- | --- |
| 형상 관리 | SSAFY GitLab — `https://lab.ssafy.com/s15-webmobile1-sub1/S15P11A206.git` |
| CI/CD | Jenkins `https://i15a206.p.ssafy.io/jenkins/` (내부 포트 `18080`) |
| 파이프라인 | `Jenkinsfile` — Backend CI(임시 MySQL 컨테이너로 테스트) → Frontend CI(`npm run build` + 번들 문자열 검증) → Backend CD(jar 교체 + systemd 재시작 + health check 30회) → Frontend CD(`dist` 배포 + HTTPS 검증) |
| 배포 경로 | 백엔드 `/opt/pingo/backend/releases/pingo-backend.jar`, 프론트 `/opt/pingo/frontend/releases/current` |
| CI 결과 연동 | `gitlabCommitStatus` 로 GitLab MR에 표시 |

> 평가자가 자기 저장소·자기 CI를 쓴다면 이 절은 참고용이다. Jenkins 없이도 §"빠른 실행" 대로
> 로컬에서 빌드·실행할 수 있고, 서버 배포는 jar를 올리고 systemd로 띄우면 된다.

### 3.2 새로 구축할 때 걸리는 것들

| 항목 | 내용 |
| --- | --- |
| **시크릿 파일** | 운영 시크릿은 Git에 없다. `/opt/pingo/backend/config/pingo-backend.env` 를 직접 만들고 `chmod 600` 해야 한다. 없으면 카카오·GMS·TURN이 기본값(dummy)으로 떨어진다 |
| **`JWT_SECRET`** | 현재 운영 서버에도 설정하지 않아 저장소의 기본값이 서명 키로 쓰이고 있다. 실서비스로 운영한다면 `openssl rand -base64 48` 로 만들어 env에 넣고 재시작해야 한다. 교체하면 기존 토큰이 무효가 되어 **상담자 재로그인이 필요**하다 |
| **WebSocket 버퍼** | `SIGNALING_WEBSOCKET_MAX_TEXT_MESSAGE_BUFFER_SIZE` 를 기본 8KB로 두면 SDP가 잘려 WS가 1009로 끊긴다. `1048576` 유지 필수 |
| **Nginx `/ws/` 타임아웃** | `proxy_read_timeout 3600s` 가 없으면 상담 중 연결이 끊긴다 |
| **업로드 3중 제한** | Nginx `12m`, 백엔드 요청 `15MB`, 파일 `10MB`. 하나만 올려도 소용없다 |
| **Flyway `validate`** | 스키마를 손으로 바꾼 뒤 재배포하면 부팅이 실패한다. 반드시 마이그레이션 파일로 관리한다 |
| **AI 서버 주소** | Jenkins가 systemd drop-in으로 주입한다. 현재 값은 Tailscale 사설 주소라 다른 네트워크에서는 접근 불가하다 |
| **TURN** | coturn은 `docker compose --profile webrtc up -d coturn` 로 별도 기동한다. `infra/coturn/turnserver.conf.example` 을 복사해 실제 값을 채운다 |
| **롤백** | 이전 jar(`pingo-backend.previous.jar`)와 프론트 `previous` 디렉터리로 복구. 상세는 `docs/Backend_배포_Rollback_절차.md` |

## 4. DB 접속 정보 · 주요 계정 · 프로퍼티 정의 파일 목록

### 4.1 DB 접속 정보

| 환경 | DB | 계정 | 비밀번호 |
| --- | --- | --- | --- |
| 로컬 (docker-compose) | `pingo` | `pingo` | `pingo` |
| 로컬 관리 계정 | — | `root` | `root` |
| 운영 EC2 | `pingo` | `pingo-backend.env` 의 `SPRING_DATASOURCE_USERNAME` | 같은 파일의 `SPRING_DATASOURCE_PASSWORD` |

접속 URL: `jdbc:mysql://localhost:3306/pingo?serverTimezone=Asia/Seoul&characterEncoding=UTF-8`

> `application-local.yaml` 의 기본값은 `root`/`1234` 인데 compose의 root 비밀번호는 `root` 다.
> **로컬 실행 시 `DB_PASSWORD=root` 를 반드시 준다.**

### 4.2 애플리케이션 주요 계정

| 구분 | 로그인 ID | 비밀번호 | 비고 |
| --- | --- | --- | --- |
| 관리자 | `admin` | `AdminBootstrap!2026` | **시드 계정** (`V6__seed_bootstrap_admin_account.sql`). 클론 후 첫 기동이면 그대로 로그인된다 |
| 상담자 | 직접 가입 | 가입 시 지정 | `POST /api/auth/signup` (공개 API, 위 "빠른 실행" 참조) |
| 관광객 | 로그인 없음 | — | 임시 `userSessionId` 발급 |

관리자 계정은 마이그레이션에 bcrypt 해시로 들어 있어 **DB를 새로 만들어도 항상 같은 값**이다.
운영 서버에 그대로 두었다면 배포 후 비밀번호를 바꾸는 것이 좋다.
