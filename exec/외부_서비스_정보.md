# PinGo 외부 서비스 정보


## 0. 제출 양식 예시 항목 대조

| 예시 항목 | 사용 여부 |
| --- | --- |
| 소셜 인증 (OAuth) | ❌ 사용 안 함. 관광객은 임시 세션, 상담자·관리자는 자체 JWT 로그인 |
| 포톤 클라우드 | ❌ 사용 안 함. 자체 Spring WebSocket 시그널링 + WebRTC P2P + 자체 coturn |
| 코드 컴파일 서비스 | ❌ 사용 안 함 |

PinGo가 실제로 쓰는 외부 서비스는 아래 4종이다. **이 중 가입이 필요한 것은 2개**(카카오, GMS)다.

| 서비스 | 가입 | 없으면 |
| --- | --- | --- |
| 카카오 로컬 API | 필요 | 역·목적지 검색, 도보 경로만 실패 |
| SSAFY GMS | 필요 | 상담 요약·자막 번역·음성 전사만 실패 |
| Google STUN | 불필요 | — |
| Let's Encrypt | 불필요 (운영만) | — |

> 둘 다 **없어도 앱은 기동하고 핵심 기능(실내 지도·경로 안내·상담 연결)은 동작한다.**

## 1. 카카오 로컬 API

역 검색 · 주변 역 조회 · 목적지 검색 · 도보 경로에 쓴다.

### 발급 방법

1. [Kakao Developers](https://developers.kakao.com) 로그인 → **내 애플리케이션** → 앱 생성
2. **앱 설정 → 앱 키 → REST API 키** 복사
3. 끝.

> **키는 반드시 필요하다.** "REST API로 호출한다"는 것은 부르는 방식을 말할 뿐이고, 그 호출에
> `Authorization: KakaoAK {REST_API_KEY}` 헤더가 들어간다. 키가 없으면 카카오가 401로 거절한다.
>
> 다만 **REST API 키 하나면 끝**이고, 아래는 하지 않아도 된다.
>
> - 콘솔에서 길찾기·지도 API 별도 활성화 — 불필요
> - 플랫폼(웹 도메인) 등록 — 불필요 (서버에서 부르므로)
> - 카카오 로그인·동의 항목 설정 — 불필요 (소셜 인증 미사용)
> - JavaScript·Admin·Native 키 — 사용하지 않음

### 적용 방법

| 위치 | 방법 |
| --- | --- |
| 로컬 | `KAKAO_REST_API_KEY=<발급받은 카카오 REST API 키> ./gradlew bootRun` |
| 운영 | `/opt/pingo/backend/config/pingo-backend.env` 에 `KAKAO_REST_API_KEY=<발급받은 카카오 REST API 키>` 추가 후 `sudo systemctl restart pingo-backend` |

### 호출 정보

| 항목 | 값 |
| --- | --- |
| 엔드포인트 | `https://dapi.kakao.com` |
| 인증 | `Authorization: KakaoAK {REST_API_KEY}` 헤더 |
| 타임아웃 | connect `1000ms` / read `3000ms` |
| 사용 API | `/v2/local/search/keyword.json`, `/v2/local/search/category.json`, `/v2/routing/walk` |

## 2. SSAFY GMS (Gemini · OpenAI 프록시)

상담 요약 · 실시간 자막 번역 · 음성 전사 3개 기능이 **키 하나**를 공유한다.

### 발급 방법


| 위치 | 방법 |
| --- | --- |
| 로컬 | `GMS_KEY=<발급받은 GMS 키> ./gradlew bootRun` |
| 운영 | `pingo-backend.env` 에 `GMS_KEY=<발급받은 GMS 키>` 추가 후 서비스 재시작 |

### 호출 정보

| 기능 | 엔드포인트 | 인증 헤더 | 모델 |
| --- | --- | --- | --- |
| 요약 | `https://gms.ssafy.io/gmsapi/generativelanguage.googleapis.com/v1beta` | `x-goog-api-key` | `gemini-2.5-flash-lite` |
| 번역 | 요약과 동일 | `x-goog-api-key` | 요약 모델 상속 |
| 전사 | `https://gms.ssafy.io/gmsapi/api.openai.com/v1` | `Authorization: Bearer` | `whisper-1` |

> ⚠️ GMS 키는 구글 키 형식(`AIza...`)이 **아니다.** 구글 공식 엔드포인트로 직접 호출하면
> 거절되므로 반드시 위 GMS 프록시 주소를 쓴다.

## 3. Google STUN 서버

| 항목 | 내용 |
| --- | --- |
| 용도 | WebRTC NAT 통과용 공인 IP 확인 |
| 주소 | `stun:stun.l.google.com:19302` |
| 가입 | **불필요** (공개 무료, 키 없음) |
| 환경변수 | `WEBRTC_STUN_URLS` (백엔드), `VITE_STUN_URL` (프론트) |

대칭형 NAT 환경에서는 STUN만으로 부족해 TURN이 필요하다 (§5 참조).

## 5. 자체 운영 서비스 (외부 가입 불필요)

외부 SaaS가 아니라 직접 구축·운영하는 것들이다. 


| 서비스 | 내용 |
| --- | --- |
| **coturn (TURN)** | `coturn/coturn:4` Docker. `docker compose --profile webrtc up -d coturn` 로 기동하고 `infra/coturn/turnserver.conf.example` 을 복사해 `realm`·인증서 경로·공인 IP·계정을 채운다. 포트 `3478`/`5349`, relay UDP `49152-65535` 개방 필요 |
| **HLOC 측위 서버** | Docker 컨테이너, 포트 `8000`. 아래 참조 |

### ⚠️ HLOC 측위 서버는 그대로 재현할 수 없다

운영 중인 AI 서버는 **팀원 개인 노트북(GPU)에서 돌고 있고** EC2와는 Tailscale 사설망으로
연결돼 있다. Jenkins가 주입하는 `AI_LOCALIZATION_BASE_URL=http://100.66.53.58:8000` 이 그
사설 주소이므로 **다른 네트워크에서는 접근할 수 없다.**

**측위 서버 없이 실행하는 것이 기본 경로다.** 카메라 기반 위치 인식만 동작하지 않고, 실내 지도·
경로 안내·상담 연결 등 나머지 기능은 모두 정상이다. 데스크톱 브라우저에서는 어차피 WebXR이
동작하지 않아 "지도만 보고 이동하기" 로 진행된다.

직접 구축하려면 `ai/deploy/ec2-cpu`(CPU) 또는 `ai/deploy/laptop-gpu`(GPU) 프로파일로 Docker를
기동하고, 백엔드의 `AI_LOCALIZATION_BASE_URL` 을 그 주소로 지정한다. 맵셋 데이터
(`AI_MAPS_HOST_PATH`)가 별도로 필요하다.
