# 외국인 관광객 대상 지하철 실내 내비게이션 사용자 시나리오

## 1. 문서 목적

본 문서는 외국인 관광객 대상 지하철 실내 내비게이션 서비스의 주요 사용 흐름을 정의한다.

대상 역이 아직 확정되지 않았더라도 서비스의 핵심 흐름은 동일하므로, 본 문서는 특정 역에 종속되지 않는 공통 사용자 시나리오를 기준으로 작성한다.

이 문서는 관련 설계와 개발의 기준 문서로 사용한다.

- 화면 흐름도
- 화면 정의서
- 기능 요구사항 명세서
- API 명세서
- 테스트 시나리오
- 시연 계획서

---

## 2. 주요 사용자 유형

### 2.1 관광객 사용자

한국 지하철역 내부 구조에 익숙하지 않고, 출구 번호나 역 내부 시설 위치를 잘 모르는 외국인 관광객이다.

주요 목표는 다음과 같다.

- 현재 위치를 확인한다.
- 목적지 또는 역 주변 장소와 가까운 출구를 찾는다.
- 출구, 승강장, 엘리베이터, 화장실 등 역 내부 목적지까지 이동한다.
- 출구 도착 후 외부 지도 앱으로 목적지까지 길찾기를 이어간다.
- 문제가 생기면 역무원 상담을 요청한다.

### 2.2 상담자·역무원

사용자의 상담 요청을 받고 영상, 음성, 지도 정보를 기반으로 사용자를 돕는 사용자이다.

주요 목표는 다음과 같다.

- 상담자 계정으로 로그인한다.
- 담당 역의 상담 요청을 확인한다.
- 사용자의 현재 위치와 목적지를 확인한다.
- 영상 또는 음성으로 사용자를 안내한다.
- 사용자 화면에 방향 표시 또는 목적지를 지정한다.

### 2.3 서비스 관리자

역, 지도, 시설, 경로, 상담자 정보를 관리하는 사용자이다.

주요 목표는 다음과 같다.

- 역과 층 정보를 관리한다.
- 시설과 출구 정보를 관리한다.
- 경로 노드와 간선 정보를 관리한다.
- 역 주변 장소와 출구 연결 정보를 관리한다.
- 상담자 계정을 관리한다.

### 2.4 동행 사용자

같은 역 내부에서 다른 사용자와 만나기 위해 위치 공유 기능을 사용하는 사용자이다.

위치 공유는 MVP 필수 기능이 아닌 도전 기능으로 분류한다.

## 3. 공통 전제

### 3.1 서비스 형태

- 서비스는 웹앱으로 제공한다.
- 일반 관광객 사용자는 로그인 없이 이용한다.
- 상담자와 관리자는 로그인 후 전용 페이지를 이용한다.
- 사용자는 카메라, 위치정보, 마이크 권한을 필요 시 허용한다.

### 3.2 MVP 전제

- MVP 대상 역은 1개로 제한한다.
- 대상 역이 바뀌어도 사용자 흐름은 동일하게 유지한다.
- 현재 위치 인식은 VPS를 우선 사용한다.
- VPS가 실패할 경우 QR/마커, 랜드마크 선택, 지도 수동 선택으로 보완한다.
- 외부 지도 앱 연계는 네이버지도를 우선 적용한다.
- 한국어와 영어를 우선 지원한다.

### 3.3 주요 상태

사용자 앱은 다음 상태를 가진다.

| 상태 | 설명 |
| --- | --- |
| 역 미선택 | 사용자가 아직 현재 역을 확정하지 않은 상태 |
| 역 선택 완료 | 사용자가 현재 역을 선택하거나 확인한 상태 |
| 위치 미확정 | 역은 선택했지만 역 내부 현재 위치가 확정되지 않은 상태 |
| 위치 확정 | 현재 층, 위치, 방향이 확인된 상태 |
| 목적지 선택 완료 | 사용자가 역 내부 시설 또는 역 주변 장소를 선택한 상태 |
| 경로 안내 중 | 현재 위치에서 목적지까지 안내 중인 상태 |
| 출구 도착 | 사용자가 출구에 도착해 외부 지도 앱 연계가 가능한 상태 |
| 상담 요청 중 | 사용자가 역무원 상담 연결을 기다리는 상태 |
| 상담 중 | 사용자와 상담자가 WebRTC로 연결된 상태 |

## 4. 시나리오 1: 외국인 관광객이 역 주변 장소까지 이동

### 4.1 목적

사용자가 출구 번호를 모르더라도 역 주변 장소를 선택하면, 서비스가 적절한 출구를 추천하고 출구까지 실내 길찾기를 제공한다.

### 4.2 주요 사용자

- 관광객 사용자

### 4.3 사전 조건

- 사용자가 지하철역 내부에 있다.
- 사용자가 웹앱에 접속할 수 있다.
- 사용자의 현재 역을 GPS 또는 직접 선택으로 확인할 수 있다.

### 4.4 기본 흐름

```text
1. 사용자가 웹앱에 접속한다.
2. 사용자가 언어를 선택한다.
3. 서비스가 위치정보 권한을 요청한다.
4. 사용자가 위치정보 권한을 허용한다.
5. 서비스가 주변 지하철역 후보를 표시한다.
6. 사용자가 현재 역을 확인하거나 직접 선택한다.
7. 사용자가 역 주변 장소를 검색한다.
8. 서비스가 장소 검색 결과를 표시한다.
9. 사용자가 목적지를 선택한다.
10. 서비스가 목적지와 가장 가까운 출구를 추천한다.
11. 서비스가 카메라 권한을 요청한다.
12. 사용자가 카메라 권한을 허용한다.
13. 사용자가 주변을 카메라로 비춘다.
14. 서비스가 현재 위치를 인식한다.
15. 서비스가 현재 위치에서 추천 출구까지 경로를 생성한다.
16. 서비스가 지도, 안내 문장, 카메라 방향 표시로 이동을 안내한다.
17. 사용자가 출구에 도착한다.
18. 서비스가 외부 지도 앱 길찾기 버튼을 제공한다.
19. 사용자가 네이버지도 길찾기를 실행한다.
```

### 4.5 대체 흐름

| 상황 | 처리 |
| --- | --- |
| GPS가 부정확함 | 사용자가 역을 직접 선택한다 |
| 장소 검색 결과가 없음 | 카테고리 또는 인기 장소 목록을 제공한다 |
| 출구 매칭 정보가 없음 | 사용자가 출구를 직접 선택하거나 상담을 요청한다 |
| 위치 인식 실패 | 재촬영, 랜드마크 선택, 지도 수동 선택을 제공한다 |
| 외부 지도 앱 연계 실패 | 웹 링크 또는 주소 복사 기능을 제공한다 |

### 4.6 완료 조건

- 사용자가 역 주변 장소를 선택할 수 있다.
- 서비스가 해당 장소와 가까운 출구를 추천한다.
- 사용자가 출구까지 실내 경로 안내를 받을 수 있다.
- 출구 도착 후 외부 지도 앱으로 이동을 이어갈 수 있다.

## 5. 시나리오 2: 출구 번호를 모르는 사용자

### 5.1 목적

사용자가 출구 번호를 모르는 상태에서도 목적지 이름만으로 올바른 출구를 찾을 수 있도록 한다.

### 5.2 주요 사용자

- 관광객 사용자

### 5.3 기본 흐름

```text
1. 사용자가 웹앱에 접속한다.
2. 사용자가 현재 역을 선택한다.
3. 사용자가 목적지 검색창에 호텔, 관광지, 음식점 등 장소명을 입력한다.
4. 서비스가 역 주변 장소 검색 결과를 표시한다.
5. 사용자가 장소를 선택한다.
6. 서비스가 해당 장소와 연결된 출구를 표시한다.
7. 사용자가 추천 출구를 확인한다.
8. 서비스가 현재 위치 인식을 요청한다.
9. 사용자가 카메라로 주변을 비춘다.
10. 서비스가 현재 위치를 확인한다.
11. 서비스가 현재 위치에서 추천 출구까지 길찾기를 시작한다.
```

### 5.4 화면에 표시할 핵심 정보

- 선택한 장소명
- 추천 출구 번호
- 출구까지 예상 이동 시간
- 출구까지 이동 거리
- 외부 목적지까지 이어가기 가능 여부

### 5.5 완료 조건

- 사용자가 출구 번호를 몰라도 목적지를 검색할 수 있다.
- 서비스가 목적지와 가까운 출구를 추천할 수 있다.
- 추천 출구를 실내 길찾기 목적지로 설정할 수 있다.

---

## 6. 시나리오 3: 지하철에서 내린 직후 출구까지 이동

### 6.1 목적

사용자가 지하철에서 내린 직후 승강장 또는 환승 구역에서 출구까지 이동할 수 있도록 한다.

### 6.2 주요 사용자

- 관광객 사용자

### 6.3 기본 흐름

```text
1. 사용자가 지하철에서 내린다.
2. 사용자가 웹앱에 접속한다.
3. 서비스가 현재 역 후보를 표시한다.
4. 사용자가 현재 역을 확인한다.
5. 사용자가 목적지 또는 출구를 선택한다.
6. 사용자가 카메라로 주변 승강장 또는 안내판을 비춘다.
7. 서비스가 현재 층과 위치를 인식한다.
8. 서비스가 승강장에서 개찰구 또는 출구까지 경로를 생성한다.
9. 서비스가 이동 방향과 다음 행동을 안내한다.
10. 사용자가 개찰구를 통과한다.
11. 서비스가 출구 방향으로 계속 안내한다.
12. 사용자가 출구에 도착한다.
```

### 6.4 대체 흐름

| 상황 | 처리 |
| --- | --- |
| 승강장 위치 인식 실패 | 안내판 재촬영 또는 승강장 방향 선택 |
| 개찰구 안팎 구분 실패 | 사용자에게 개찰구 통과 여부를 묻는다 |
| 층 이동 필요 | 계단, 에스컬레이터, 엘리베이터 중 경로 옵션을 제공한다 |

### 6.5 완료 조건

- 사용자가 지하철에서 내린 직후 현재 위치를 잡을 수 있다.
- 승강장 또는 환승 구역에서 출구까지 경로를 생성할 수 있다.
- 개찰구 통과 후에도 안내 흐름을 유지할 수 있다.

---

## 7. 시나리오 4: 계단·에스컬레이터를 피하는 경로 이용

### 7.1 목적

큰 짐, 휠체어, 유모차를 이용하는 사용자가 계단과 에스컬레이터를 피하고 엘리베이터 중심 경로를 이용할 수 있도록 한다.

### 7.2 주요 사용자

- 관광객 사용자

### 7.3 기본 흐름

```text
1. 사용자가 웹앱에 접속한다.
2. 사용자가 경로 옵션에서 엘리베이터 중심 경로를 선택한다.
3. 사용자가 현재 역을 확인한다.
4. 사용자가 목적지를 선택한다.
5. 서비스가 현재 위치를 인식한다.
6. 서비스가 엘리베이터를 우선 사용하는 경로를 생성한다.
7. 서비스가 빠른 경로, 계단 없는 경로, 엘리베이터 중심 경로를 비교해 보여준다.
8. 사용자가 엘리베이터 중심 경로를 선택한다.
9. 서비스가 엘리베이터 위치까지 안내한다.
10. 사용자가 엘리베이터를 이용해 층을 이동한다.
11. 서비스가 층 이동 후 위치 재인식을 요청한다.
12. 서비스가 목적지까지 남은 경로를 안내한다.
```

### 7.4 화면에 표시할 핵심 정보

- 엘리베이터 위치
- 이동해야 하는 층
- 예상 이동 시간
- 계단 포함 여부
- 빠른 경로와의 차이

### 7.5 완료 조건

- 엘리베이터 중심 경로를 생성할 수 있다.
- 층 이동 후 위치 재인식을 수행할 수 있다.
- 빠른 경로, 계단 없는 경로, 엘리베이터 중심 경로를 구분해서 표시할 수 있다.

---

## 8. 시나리오 5: VPS 인식 실패 후 수동 위치 선택

### 8.1 목적

VPS가 실패하더라도 사용자가 서비스를 계속 이용할 수 있도록 대체 흐름을 제공한다.

### 8.2 주요 사용자

- 관광객 사용자

### 8.3 기본 흐름

```text
1. 사용자가 현재 위치 인식을 시작한다.
2. 사용자가 카메라로 주변을 비춘다.
3. 서비스가 VPS 위치 인식을 시도한다.
4. 서비스가 낮은 신뢰도 또는 인식 실패 결과를 반환한다.
5. 서비스가 사용자에게 재촬영을 요청한다.
6. 사용자가 다른 방향으로 주변을 다시 촬영한다.
7. 서비스가 다시 위치 인식을 시도한다.
8. 그래도 실패하면 서비스가 주변 랜드마크 후보를 표시한다.
9. 사용자가 현재 보이는 랜드마크를 선택한다.
10. 서비스가 선택된 랜드마크 주변을 현재 위치 후보로 설정한다.
11. 사용자가 지도에서 현재 위치를 보정한다.
12. 서비스가 보정된 위치를 기준으로 경로를 생성한다.
```

### 8.4 대체 흐름

| 상황 | 처리 |
| --- | --- |
| 사용자가 랜드마크를 찾지 못함 | 지도에서 직접 현재 위치 선택 |
| 지도에서도 위치를 모르겠음 | 역무원 상담 요청으로 연결 |
| 네트워크 문제로 VPS 요청 실패 | 마지막 위치 또는 수동 위치 선택으로 전환 |

### 8.5 완료 조건

- VPS 실패 상태를 사용자에게 명확히 알린다.
- 재촬영, 랜드마크 선택, 지도 수동 선택 중 하나를 제공한다.
- 대체 위치를 기준으로 경로를 다시 생성한다.

---

## 9. 시나리오 6: WebRTC 역무원 상담

### 9.1 목적

자동 안내로 해결하기 어려운 상황에서 사용자가 해당 역의 역무원 또는 상담자에게 도움을 받을 수 있도록 한다.

### 9.2 주요 사용자

- 관광객 사용자
- 상담자·역무원

### 9.3 사용자 기본 흐름

```text
1. 사용자가 경로 안내 중 문제를 겪는다.
2. 사용자가 상담 요청 버튼을 누른다.
3. 서비스가 문제 유형 선택 화면을 표시한다.
4. 사용자가 문제 유형을 선택한다.
5. 서비스가 현재 역, 현재 위치, 목적지 정보를 상담 요청에 포함한다.
6. 사용자가 카메라와 마이크 공유에 동의한다.
7. 서비스가 해당 역 상담자에게 상담 요청을 전달한다.
8. 상담자가 요청을 수락한다.
9. 사용자와 상담자가 WebRTC 영상 또는 음성으로 연결된다.
10. 사용자가 카메라로 주변 상황을 보여준다.
11. 상담자가 사용자에게 이동 방향을 안내한다.
12. 상담자가 필요 시 지도 위 목적지 또는 시설을 지정한다.
13. 사용자 앱이 상담자가 지정한 목적지 기준으로 경로를 갱신한다.
14. 사용자가 상담을 종료한다.
```

### 9.4 상담자 기본 흐름

```text
1. 상담자가 로그인한다.
2. 서비스가 상담자 전용 페이지로 이동한다.
3. 상담자가 담당 역의 상담 요청 목록을 확인한다.
4. 상담자가 요청 상세 정보를 확인한다.
5. 상담자가 상담을 수락한다.
6. 상담자가 사용자 영상, 현재 위치, 목적지, 문제 유형을 확인한다.
7. 상담자가 음성 또는 채팅으로 안내한다.
8. 상담자가 지도 위 시설 또는 목적지를 지정한다.
9. 서비스가 지정 정보를 사용자 앱에 전달한다.
10. 상담자가 상담을 종료한다.
```

### 9.5 상담 요청 유형

- 현재 위치를 찾을 수 없음
- 이동 방향을 모르겠음
- 출구를 찾을 수 없음
- 개찰구를 통과할 수 없음
- 엘리베이터 위치를 찾을 수 없음
- 발매기 또는 교통카드 사용이 어려움
- 기타 문제

### 9.6 대체 흐름

| 상황 | 처리 |
| --- | --- |
| 상담자가 없음 | 대기 상태, 역무실 위치, 기본 안내 문장 제공 |
| 영상 연결 실패 | 음성 상담으로 전환 |
| 음성 연결 실패 | 채팅 상담 또는 안내 문장 제공 |
| 사용자가 카메라 공유 거부 | 지도 위치와 텍스트 기반 상담 진행 |
| 상담 도중 연결 끊김 | 재연결 버튼과 마지막 안내 경로 유지 |

### 9.7 완료 조건

- 사용자가 상담 요청을 보낼 수 있다.
- 상담자가 전용 페이지에서 요청을 확인하고 수락할 수 있다.
- WebRTC 영상 또는 음성 연결이 가능하다.
- 상담자가 지정한 목적지 또는 시설이 사용자 앱에 반영된다.

---

## 10. 시나리오 7: 상담자 전용 페이지에서 상담 처리

### 10.1 목적

상담자가 일반 사용자 화면과 분리된 전용 페이지에서 상담 요청을 처리할 수 있도록 한다.

### 10.2 주요 사용자

- 상담자·역무원

### 10.3 기본 흐름

```text
1. 상담자가 상담자 로그인 페이지에 접속한다.
2. 상담자가 계정 정보를 입력한다.
3. 서비스가 상담자 권한을 확인한다.
4. 상담자가 상담자 전용 페이지로 이동한다.
5. 서비스가 담당 역의 상담 요청 목록을 표시한다.
6. 상담자가 상담 요청을 선택한다.
7. 서비스가 요청 상세 정보를 표시한다.
8. 상담자가 상담을 수락한다.
9. 상담자가 사용자 영상 또는 음성 연결을 시작한다.
10. 상담자가 사용자 현재 위치와 목적지를 확인한다.
11. 상담자가 지도 위에서 안내할 시설 또는 목적지를 선택한다.
12. 서비스가 선택 정보를 사용자 앱에 전송한다.
13. 상담자가 상담을 종료하고 상담 결과를 저장한다.
```

### 10.4 상담자 화면 핵심 정보

- 상담 요청 목록
- 사용자 현재 역
- 사용자 현재 위치
- 사용자 목적지
- 문제 유형
- 상담 대기 시간
- 사용자 영상 화면
- 지도 화면
- 시설 또는 목적지 지정 버튼
- 상담 종료 버튼

### 10.5 완료 조건

- 상담자가 로그인할 수 있다.
- 상담자 전용 페이지에서 요청 목록을 볼 수 있다.
- 상담자가 상담을 수락하거나 종료할 수 있다.
- 상담자가 사용자 앱에 목적지 또는 시설 지정 정보를 보낼 수 있다.

---

## 11. 시나리오 8: 외부 지도 앱 연계

### 11.1 목적

사용자가 지하철역 출구에 도착한 뒤 외부 목적지까지 길찾기를 자연스럽게 이어갈 수 있도록 한다.

### 11.2 주요 사용자

- 관광객 사용자

### 11.3 기본 흐름

```text
1. 사용자가 역 주변 장소를 목적지로 선택한다.
2. 서비스가 가까운 출구를 추천한다.
3. 사용자가 출구까지 실내 길찾기를 완료한다.
4. 서비스가 출구 도착 상태를 표시한다.
5. 서비스가 외부 지도 앱 연계 버튼을 표시한다.
6. 사용자가 네이버지도 버튼을 선택한다.
7. 네이버지도 앱 또는 웹 지도가 열린다.
8. 외부 지도에서 출구 위치부터 최종 목적지까지 길찾기가 시작된다.
```

### 11.4 연계 정보

외부 지도 앱에는 다음 정보가 전달되어야 한다.

- 출발지: 도착한 출구 위치
- 도착지: 사용자가 선택한 역 주변 장소
- 이동 방식: 도보 우선

### 11.5 대체 흐름

| 상황 | 처리 |
| --- | --- |
| 외부 지도 앱이 설치되어 있지 않음 | 웹 지도 링크로 연결 |
| 지도 앱 링크 실행 실패 | 목적지 주소 또는 장소명 복사 기능 제공 |
| 출구 도착 확인이 불확실함 | 사용자가 직접 출구 도착 버튼을 누른다 |

### 11.6 완료 조건

- 출구 도착 후 외부 지도 앱 연계 버튼이 표시된다.
- 네이버지도 앱 또는 웹 지도에서 목적지까지 길찾기가 시작된다.
- 앱 미설치 상황에서도 웹 링크로 대체할 수 있다.

---

## 12. 시나리오 9: 교통카드 간단 추천

### 12.1 목적

사용자의 여행 조건에 따라 적합한 교통카드 유형을 간단히 추천한다.

교통카드 추천은 MVP 후순위 기능이다.

### 12.2 주요 사용자

- 관광객 사용자

### 12.3 기본 흐름

```text
1. 사용자가 교통카드 추천 메뉴를 선택한다.
2. 서비스가 여행 기간을 입력받는다.
3. 서비스가 방문 지역을 입력받는다.
4. 서비스가 하루 예상 대중교통 이용 횟수를 입력받는다.
5. 서비스가 공항 이동 여부를 입력받는다.
6. 서비스가 조건에 맞는 교통카드 유형을 추천한다.
7. 서비스가 추천 이유와 구매 위치, 주의사항을 표시한다.
```

### 12.4 추천 결과 예시

- 일반 Tmoney
- 기후동행카드
- 1일권
- 2일권
- 일회용 승차권

### 12.5 완료 조건

- 사용자가 간단한 여행 조건을 입력할 수 있다.
- 서비스가 카드 유형을 추천한다.
- 추천 이유와 사용 시 주의사항을 표시한다.

---

## 13. 시나리오 10: 사용자 간 위치 공유

### 13.1 목적

같은 역 내부에 있는 사용자들이 서로의 위치를 공유하고, 공유된 위치까지 실내 길찾기를 이용할 수 있도록 한다.

사용자 간 위치 공유는 MVP 도전 기능이다.

### 13.2 주요 사용자

- 관광객 사용자
- 동행 사용자

### 13.3 기본 흐름

```text
1. 사용자 A가 현재 위치를 인식한다.
2. 사용자 A가 위치 공유 버튼을 누른다.
3. 서비스가 공유 링크 또는 공유 코드를 생성한다.
4. 사용자 A가 링크를 사용자 B에게 전달한다.
5. 사용자 B가 공유 링크에 접속한다.
6. 서비스가 공유된 위치를 표시한다.
7. 사용자 B가 자신의 현재 위치를 인식한다.
8. 서비스가 B의 현재 위치에서 A의 공유 위치까지 경로를 생성한다.
9. 사용자 B가 경로 안내를 따라 이동한다.
10. 공유 링크는 일정 시간이 지나면 만료된다.
```

### 13.4 대체 흐름

| 상황 | 처리 |
| --- | --- |
| 사용자 A 위치 인식 실패 | 지도에서 위치 직접 선택 후 공유 |
| 사용자 B 위치 인식 실패 | 지도에서 현재 위치 직접 선택 |
| 공유 링크 만료 | 사용자 A가 새 링크를 생성 |

### 13.5 완료 조건

- 사용자가 자신의 위치를 공유할 수 있다.
- 다른 사용자가 공유 위치를 목적지로 설정할 수 있다.
- 공유 위치까지 실내 경로를 생성할 수 있다.
- 공유 링크는 만료 시간을 가진다.
