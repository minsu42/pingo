# 외국인 관광객 대상 지하철 실내 내비게이션 화면 정의서

> 최신화: 2026-07-30

## 1. 문서 목적

본 문서는 외국인 관광객 대상 지하철 실내 내비게이션 서비스의 화면별 구성 요소, 사용자 액션, 시스템 처리, 예외 처리를 정의한다.

본 문서는 관련 설계와 개발의 기준으로 사용한다.

- 프론트엔드 화면 개발
- 백엔드 API 설계
- WebRTC 상담 기능 설계
- 관리자 기능 설계

### 현재 화면 구현 요약

| 영역 | 현재 route/구조 | 연동 상태 |
| --- | --- | --- |
| 사용자 | splash, language, permission, station, 촬영, analyzing, 위치 성공/실패/수동, 목적지, 경로 옵션, navigation/reroute, arrival, external-map, offline, settings, 상담 요청~종료 | 주요 화면 존재, 다수 mock/fixture |
| 상담자 | login, signup, pending, requests, connecting/failed, session, history, stats | 화면 존재, 실제 WebRTC/상담 처리 API 미연동 |
| 관리자 | login + 하나의 console 안 station/map/facility/route/place/counselor 6개 tab | Backend CRUD 다수 구현, 화면별 연동 확인 필요 |

U-16·U-17처럼 독립 route가 없는 정의는 목표 기능이며, route가 존재한다고 간주하지 않는다.
- QA 테스트 케이스 작성

## 2. 공통 화면 기준

### 2.1 서비스 형태

- 서비스는 모바일 웹앱을 우선 기준으로 설계한다.
- 일반 사용자는 로그인 없이 이용한다.
- 상담자와 관리자는 각각 별도 로그인 화면을 사용한다.
- 사용자 화면, 상담자 화면, 관리자 화면은 URL과 권한을 분리한다.

### 2.2 공통 UI 원칙

- 외국인 관광객이 빠르게 이해할 수 있도록 텍스트는 짧게 작성한다.
- MVP에서는 한국어와 영어를 우선 지원한다.
- 주요 기능 버튼은 아이콘과 텍스트를 함께 사용한다.
- 상담 버튼은 가능한 많은 화면에서 접근 가능하게 둔다.
- 경로 안내 화면은 상단 카메라, 하단 지도를 기본 구조로 한다.
- 권한 거부, VPS 실패, 네트워크 오류 등 실패 상황에서는 다음 행동을 명확히 제공한다.

### 2.3 공통 버튼

| 버튼 | 노출 위치 | 설명 |
| --- | --- | --- |
| 상담 요청 | 주요 사용자 화면 | 역무원 상담 요청 화면으로 이동 |
| 다시 시도 | 실패 화면 | 현재 작업 재시도 |
| 지도에서 선택 | 위치 인식 실패 화면 | 사용자가 현재 위치를 수동 선택 |
| 경로 시작 | 목적지/출구 확인 화면 | 경로 안내 시작 |
| 현재 위치 다시 인식 | 경로 안내 화면 | VPS 또는 보조 인식 재시도 |
| 출구에 도착했어요 | 경로 안내 화면 | 사용자가 출구 도착을 수동 확인 |

### 2.4 공통 데이터

| 데이터 | 설명 |
| --- | --- |
| selectedLanguage | 사용자가 선택한 언어 |
| selectedStation | 사용자가 확정한 현재 역 |
| currentIndoorLocation | 역 내부 현재 위치 |
| currentGpsLocation | GPS 기반 실제 현재 위치 |
| destination | 사용자가 선택한 최종 목적지 |
| indoorTarget | 실내 길찾기 목적지 |
| route | 실내 경로 |
| navigationState | 경로 안내 상태 |
| consultationSession | 상담 세션 정보 |

## U-02. 권한 요청 화면

### 화면 목적

서비스 이용에 필요한 위치정보, 카메라, 마이크 권한을 요청한다.

### 진입 경로

- 언어 선택 완료 후 자동 진입

### UI 구성

| 요소 | 유형 | 설명 |
| --- | --- | --- |
| 권한 안내 문구 | 텍스트 | 필요한 권한과 이유 설명 |
| 위치정보 권한 항목 | 상태 표시 | 현재 역 탐색과 외부 지도 연계에 필요 |
| 카메라 권한 항목 | 상태 표시 | VPS 위치 인식과 안내 화면에 필요 |
| 마이크 권한 항목 | 상태 표시 | WebRTC 음성 상담에 필요 |
| 권한 허용 버튼 | 버튼 | 브라우저 권한 요청 시작 |
| 권한 없이 계속하기 | 버튼 | 제한 모드로 진행 |

### 사용자 액션

| 액션 | 처리 |
| --- | --- |
| 권한 허용 | 위치, 카메라, 마이크 권한 요청 |
| 권한 없이 계속하기 | 직접 역 선택과 수동 위치 선택 흐름으로 이동 |

### 시스템 처리

- 브라우저 권한 API를 호출한다.
- 권한 허용 상태를 저장한다.
- 권한별 거부 상태를 이후 화면에서 반영한다.

| 출구에 도착했어요 | 버튼 | 출구 도착 수동 확인 |
| 상담 요청 버튼 | 고정 버튼 | 상담 요청 |
| 추적 상태 표시 | 배지 | `실시간 추적 중` 또는 `추적 미지원 · 재인식 필요`. WebXR 미지원·권한 거부·세션 실패 시 후자를 표시 |

### 사용자 액션

| 액션 | 처리 |
| --- | --- |
| 현재 위치 다시 인식 | **U-04 화면으로 이동한다.** 3방향 주변 촬영으로 위치를 새로 확정하고 U-05를 거쳐 이 화면으로 돌아온다. 화면을 벗어나므로 XR 세션이 끊기고 추적 앵커가 폐기되는데, 이 버튼을 누르는 상황은 이미 위치를 신뢰할 수 없는 때(경로 이탈, 엘리베이터 하차)라 지킬 앵커가 없다 |
| 출구에 도착했어요 | 출구 도착 확인 화면 이동 |
| 상담 요청 | 상담 요청 화면 이동 |
| 경로 이탈 감지 확인 | 현재 위치 기준 경로 재계산 |

**U-05에서 돌아올 화면이 갈린다.** U-05의 기본 CTA는 경로 옵션 선택(U-08)이므로, 안내 중 재인식임을 표시하지 않으면 사용자가 목적지 선택부터 다시 밟는다. 안내 중 재인식이면 U-05가 이 화면으로 돌아오는 CTA를 표시한다.

### 세션 안 위치 인식 (사용자 액션이 아니다)

위 버튼과 **별개의 흐름이다.** 상대 위치 추적의 앵커를 만들고 갱신하기 위해 시스템이 수행하며, 사용자 조작이 없고 화면을 벗어나지 않는다. `camera-access`로 세션을 유지한 채 프레임을 얻는다(`기술_의사결정_정리.md` 11.8). 추적이 잡히면 자동 1회 수행한다.

두 흐름의 구분은 `기술_의사결정_정리.md` 12장에 표로 있다.

### API 후보

| API | 설명 |
| --- | --- |
| POST /navigation/relocalize | **세션 안 위치 인식**에 쓴다. 사용자 재인식 버튼은 U-04의 위치 인식 API를 그대로 쓴다. `API_명세서.md`에 아직 없다 |
| POST /api/routes/indoor | 현재 위치 기준 경로 재계산. **전용 재계산 API 는 만들지 않는다** — 새 `startNodeId` 로 이 API 를 다시 부르면 같은 결과가 나온다 (S15P11A206-324) |

## 7. 확정된 화면 구현 기준

다음 항목은 화면 구현 기준으로 확정한다.

1. 프론트엔드는 React + TypeScript + Vite 기준으로 구현한다.
2. UI 스타일링은 CSS Modules와 CSS Variables를 사용한다.
3. 아이콘은 lucide-react를 사용한다.
4. 지도는 이미지 지도 + 좌표 오버레이 방식으로 구현한다.
5. 카메라 화면 위 화살표는 오버레이 UI로 구현한다.
6. 외부 지도는 Kakao Map 앱 링크를 우선 사용하고 웹 링크를 fallback으로 제공한다.
7. WebRTC signaling은 WebSocket으로 구현한다.
8. 관리자 화면은 역/층/지도, 시설/출구, 노드/간선, 주변 장소/추천 출구, 상담자 계정 CRUD를 우선 구현한다.
9. 상담자 계정은 관리자 화면에서 수동 등록하는 방식을 기본으로 한다.
