# 외국인 관광객 대상 지하철 실내 내비게이션 화면 흐름도

## 1. 문서 목적

본 문서는 외국인 관광객 대상 지하철 실내 내비게이션 서비스의 주요 화면 흐름을 정의한다.

서비스는 웹앱으로 제공되며, 일반 사용자는 로그인 없이 이용한다. 상담자와 관리자는 각각 별도의 로그인 및 전용 페이지를 사용한다.

본 문서는 이후 화면 정의서, API 명세서, 프론트엔드 개발 기준 문서의 기반으로 사용한다.

---

## 2. 화면 설계 기본 원칙

### 2.1 사용자 웹앱 기본 원칙

- 사용자는 별도 회원가입이나 로그인 없이 서비스를 이용한다.
- 웹앱 접속 시 가장 먼저 언어 선택 화면을 보여준다.
- 권한 요청은 초기 진입 직후 한 번에 진행한다.
- 카메라는 현재 위치 인식 시 켜지고, 경로 안내 중에도 계속 유지한다.
- 경로 안내 화면은 **상단 카메라, 하단 지도** 구조를 기본으로 한다.
- 상담 버튼은 가능한 많은 화면에서 접근 가능하게 배치한다.
- 출구 도착은 시스템이 자동 판단하되, 사용자가 직접 누를 수 있는 `출구에 도착했어요` 버튼도 제공한다.
- 외부 지도 앱 연계 시 출발지는 기존 실내 안내의 출구가 아니라 **사용자의 실제 현재 위치**를 기준으로 한다.

### 2.2 상담자 페이지 기본 원칙

- 상담자는 별도의 상담자 로그인 화면을 통해 접속한다.
- 로그인 후 일반 사용자 화면이 아닌 상담자 전용 페이지로 이동한다.
- 상담자는 담당 역의 상담 요청 목록을 확인하고 상담을 수락한다.
- 상담 화면에서는 사용자 영상, 위치, 목적지, 문제 유형, 지도 정보를 함께 확인한다.

### 2.3 관리자 페이지 기본 원칙

- 관리자는 상담자 페이지와 완전히 분리된 관리자 페이지를 사용한다.
- 관리자는 역, 지도, 시설, 경로, 주변 장소, 상담자 계정 정보를 관리한다.
- MVP에서는 기본 데이터 관리 기능 중심으로 구성한다.

## 3. 전체 화면 구조

```text
웹앱 진입
│
├─ 사용자 웹앱
│   ├─ 언어 선택
│   ├─ 권한 요청
│   ├─ 현재 역 확인
│   ├─ 현재 위치 인식
│   ├─ 목적지 검색
│   ├─ 출구 추천
│   ├─ 경로 안내
│   ├─ 출구 도착 확인
│   ├─ 외부 지도 앱 연계
│   └─ 상담 요청 / 상담 진행
│
├─ 상담자 페이지
│   ├─ 상담자 로그인
│   ├─ 상담 요청 목록
│   ├─ 상담 요청 상세
│   └─ WebRTC 상담
│
└─ 관리자 페이지
    ├─ 관리자 로그인
    ├─ 역·지도 관리
    ├─ 시설·출구 관리
    ├─ 경로 관리
    ├─ 주변 장소 관리
    └─ 상담자 계정 관리
```

## 4. 사용자 웹앱 화면 흐름

### 4.1 기본 길찾기 흐름

```text
[언어 선택]
→ [권한 요청]
→ [현재 역 확인]
→ [현재 위치 인식]
→ [목적지 검색]
→ [출구 추천 또는 목적지 확인]
→ [경로 안내]
→ [출구 도착 확인]
→ [외부 지도 앱 연계]
```

### 4.2 화면별 역할

| 순서 | 화면 | 역할 |
| --- | --- | --- |
| 1 | 언어 선택 화면 | 사용자가 서비스 언어를 선택한다 |
| 2 | 권한 요청 화면 | 위치, 카메라, 마이크 권한을 요청한다 |
| 3 | 현재 역 확인 화면 | GPS 기반 후보 역을 보여주고 사용자가 현재 역을 확정한다 |
| 4 | 현재 위치 인식 화면 | 카메라로 주변을 비춰 VPS 또는 보조 인식으로 위치를 확인한다 |
| 5 | 목적지 검색 화면 | 역 내부 시설 또는 역 주변 장소를 검색한다 |
| 6 | 출구 추천 화면 | 역 주변 장소와 가까운 출구를 추천한다 |
| 7 | 경로 안내 화면 | 카메라와 지도를 함께 보여주며 이동을 안내한다 |
| 8 | 출구 도착 확인 화면 | 출구 도착 여부를 자동 판단하고 사용자에게 확인받는다 |
| 9 | 외부 지도 앱 연계 화면 | 실제 현재 위치에서 외부 목적지까지 길찾기를 연결한다 |

## 5. 사용자 웹앱 상세 흐름

### 5.1 언어 선택 화면

```text
사용자 웹앱 접속
→ 언어 선택 화면 표시
→ 사용자가 한국어 또는 영어 선택
→ 권한 요청 화면으로 이동
```

#### 표시 요소

- 서비스명 또는 간단한 로고
- 한국어 선택 버튼
- 영어 선택 버튼
- 일본어·중국어는 추후 확장 예정 표시 또는 비노출

#### 다음 화면

- 권한 요청 화면

---

### 5.2 권한 요청 화면

웹앱 초기 진입 직후 서비스 이용에 필요한 권한을 한 번에 요청한다.

```text
권한 요청 화면 표시
→ 위치정보 권한 요청
→ 카메라 권한 요청
→ 마이크 권한 요청
→ 권한 허용 여부 확인
→ 현재 역 확인 화면으로 이동
```

#### 권한별 목적

| 권한 | 사용 목적 |
| --- | --- |
| 위치정보 | 현재 역 후보 탐색, 외부 지도 연계 시 실제 현재 위치 확인 |
| 카메라 | VPS 위치 인식, 경로 안내 중 카메라 화면 표시, 상담 시 영상 공유 |
| 마이크 | WebRTC 음성 상담 |

#### 대체 흐름

| 상황 | 처리 |
| --- | --- |
| 위치 권한 거부 | 역 직접 선택 화면으로 이동 |
| 카메라 권한 거부 | 지도 기반 수동 위치 선택 안내 |
| 마이크 권한 거부 | 상담 시 영상 또는 채팅 중심 안내 |

#### 다음 화면

- 현재 역 확인 화면

---

### 5.3 현재 역 확인 화면

```text
서비스가 GPS 기반 주변 역 후보 표시
→ 사용자가 현재 역 확인
→ 후보가 틀리면 직접 검색 또는 선택
→ 현재 위치 인식 화면으로 이동
```

#### 표시 요소

- 현재 위치 기반 역 후보
- 역 직접 검색 입력창
- 역 선택 버튼
- 상담 버튼

#### 다음 화면

- 현재 위치 인식 화면

---

### 5.4 현재 위치 인식 화면

현재 역이 확정되면 사용자의 역 내부 위치를 확인한다.

```text
카메라 화면 실행
→ 사용자에게 주변을 천천히 비추도록 안내
→ VPS 위치 인식 요청
→ 위치 후보와 신뢰도 표시
→ 사용자가 위치 확인
→ 목적지 검색 화면으로 이동
```

#### 표시 요소

- 전체 화면 또는 큰 영역의 카메라 뷰
- 촬영 안내 문구
- 위치 인식 진행 상태
- 위치 후보
- 신뢰도 표시
- 다시 인식 버튼
- 지도에서 직접 선택 버튼
- 상담 버튼

#### 대체 흐름

```text
VPS 인식 실패
→ 재촬영 요청
→ 주변 랜드마크 후보 표시
→ 지도에서 직접 선택 제공
→ 그래도 실패하면 상담 요청 유도
```

#### 다음 화면

- 목적지 검색 화면
- 위치 인식 실패 대응 화면
- 상담 요청 화면

---

### 5.5 목적지 검색 화면

```text
사용자가 목적지 검색 화면 진입
→ 역 내부 시설 또는 역 주변 장소 검색
→ 검색 결과 표시
→ 사용자가 목적지 선택
→ 목적지 유형에 따라 다음 화면 분기
```

#### 목적지 유형별 분기

| 목적지 유형 | 다음 화면 |
| --- | --- |
| 역 내부 시설 | 경로 안내 화면 |
| 특정 출구 | 경로 안내 화면 |
| 역 주변 장소 | 출구 추천 화면 |
| 공유 위치 | 경로 안내 화면 |

#### 표시 요소

- 검색창
- 역 내부 시설 카테고리
- 역 주변 장소 카테고리
- 최근 검색
- 추천 목적지
- 상담 버튼

---

### 5.6 출구 추천 화면

역 주변 장소를 선택한 경우 해당 장소와 가까운 출구를 추천한다.

```text
사용자가 역 주변 장소 선택
→ 서비스가 가장 가까운 출구 계산
→ 추천 출구와 이유 표시
→ 사용자가 출구 안내 시작
→ 경로 안내 화면으로 이동
```

#### 표시 요소

- 선택한 외부 목적지
- 추천 출구
- 출구까지 예상 이동 시간
- 출구까지 이동 거리
- 외부 목적지까지 이어가기 가능 여부
- 경로 시작 버튼
- 다른 출구 보기
- 상담 버튼

#### 다음 화면

- 경로 안내 화면

---

### 5.7 경로 안내 화면

경로 안내 화면은 서비스의 핵심 화면이다.

기본 레이아웃은 **상단 카메라, 하단 지도** 구조로 한다.

```text
경로 안내 시작
→ 상단 카메라 화면 유지
→ 카메라 위 방향 화살표 표시
→ 하단 지도에 현재 위치와 경로 표시
→ 단계별 안내 문장 표시
→ 주요 지점에서 위치 재인식
→ 목적지 또는 출구 도착 여부 판단
```

#### 화면 구성

```text
┌──────────────────────────┐
│ 상단: 카메라 화면          │
│ - 방향 화살표              │
│ - 다음 행동 안내            │
│ - 상담 버튼                │
├──────────────────────────┤
│ 하단: 실내 지도             │
│ - 현재 위치                │
│ - 목적지                  │
│ - 경로                    │
│ - 남은 거리/시간            │
└──────────────────────────┘
```

#### 표시 요소

- 카메라 화면
- 방향 화살표
- 다음 행동 안내 문장
- 남은 거리
- 예상 도착 시간
- 하단 실내 지도
- 현재 위치
- 목적지
- 경로 재인식 버튼
- 상담 버튼
- 출구에 도착했어요 버튼

#### 위치 재인식 지점

- 갈림길
- 층 이동 후
- 개찰구 통과 후
- 출구 근처
- 사용자가 재인식 버튼을 누른 경우

#### 다음 화면

- 출구 도착 확인 화면
- 목적지 도착 화면
- 위치 인식 실패 대응 화면
- 상담 요청 화면

---

### 5.8 출구 도착 확인 화면

출구 도착은 시스템이 자동 판단하되, 사용자가 직접 확인할 수 있는 버튼도 제공한다.

```text
서비스가 출구 근처 도착을 감지
→ 사용자에게 출구 도착 여부 확인
→ 사용자가 도착 확인
→ 외부 지도 앱 연계 화면으로 이동
```

#### 도착 판단 방식

- VPS 또는 보조 위치 인식 결과가 출구 근처로 판단됨
- 지도 경로상 마지막 노드에 도달함
- 사용자가 `출구에 도착했어요` 버튼을 누름

#### 표시 요소

- "출구에 도착하셨나요?" 확인 문구
- 출구명 또는 출구 번호
- 외부 길찾기 이어가기 버튼
- 아직 아니에요 버튼
- 현재 위치 다시 확인 버튼
- 상담 버튼

#### 다음 화면

- 외부 지도 앱 연계 화면
- 경로 안내 화면

---

### 5.9 외부 지도 앱 연계 화면

외부 지도 앱 연계 시 출발지는 실내 안내에서 설정한 출구가 아니라 **실제 사용자의 현재 위치**를 기준으로 한다.

이 방식은 사용자가 안내를 정확히 따르지 않고 다른 출구나 다른 위치로 밖에 나온 경우도 커버하기 위함이다.

```text
출구 도착 확인
→ 서비스가 사용자의 실제 현재 위치 확인
→ 사용자가 선택한 원래 외부 목적지 확인
→ 네이버지도 길찾기 버튼 표시
→ 사용자가 네이버지도 실행
→ 네이버지도 앱 또는 웹 지도 실행
```

#### 연계 데이터

| 항목 | 값 |
| --- | --- |
| 출발지 | 사용자의 실제 현재 GPS 위치 |
| 도착지 | 사용자가 우리 서비스에서 선택한 외부 목적지 |
| 이동 방식 | 도보 |

#### 표시 요소

- 현재 외부 목적지
- 현재 위치 기반 길찾기 안내 문구
- 네이버지도 열기 버튼
- 주소 복사 버튼
- 상담 버튼

#### 대체 흐름

| 상황 | 처리 |
| --- | --- |
| 위치 권한 없음 | 출구 위치를 출발지로 사용하거나 권한 재요청 |
| 지도 앱 실행 실패 | 웹 지도 링크로 연결 |
| 사용자가 다른 곳으로 나감 | 실제 현재 위치를 출발지로 사용해 외부 길찾기 생성 |

## 6. 사용자 상담 흐름

상담 버튼은 가능한 많은 화면에서 접근할 수 있도록 한다.

### 6.1 상담 버튼 노출 화면

| 화면 | 노출 여부 |
| --- | --- |

### 6.2 상담 요청 흐름

```text
상담 버튼 클릭
→ 문제 유형 선택
→ 영상·음성 공유 동의
→ 현재 역/현재 위치/목적지 정보 포함
→ 상담 요청 전송
→ 상담 대기
→ 상담자 수락
→ WebRTC 상담 화면
```

### 6.3 상담 요청 화면

#### 표시 요소

- 문제 유형 선택
- 현재 역
- 현재 위치
- 목적지
- 카메라 공유 동의
- 마이크 공유 동의
- 상담 요청 버튼
- 취소 버튼

### 6.4 상담 대기 화면

#### 표시 요소

- 상담 요청 상태
- 예상 대기 또는 대기 중 표시
- 가까운 역무실 안내
- 역무원에게 보여줄 문장
- 상담 취소 버튼

### 6.5 사용자 WebRTC 상담 화면

```text
상단: 사용자 카메라 또는 상담 영상
하단: 지도와 안내 정보
상담자가 지정한 화살표 또는 목적지 반영
```

#### 표시 요소

- 영상 화면
- 음성 연결 상태
- 채팅 또는 안내 문장
- 상담자가 표시한 화살표
- 상담자가 지정한 목적지
- 상담 종료 버튼

#### 다음 화면

### 7.4 상담 요청 상세 화면

├──────────────────────────┤

- 상담 종료 버튼
