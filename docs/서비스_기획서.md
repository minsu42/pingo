# 외국인 관광객 대상 지하철 실내 내비게이션 서비스 기획서

> 최신화: 2026-07-30

### 현재 구현 요약

Backend와 AI의 핵심 API/위치추정 파이프라인, React의 주요 사용자·상담자·관리자 화면은 구축돼 있다. 다만 Frontend의 실제 API 연동은 층 지도 조회 중심이고 나머지는 mock/fixture 비중이 크다. WebRTC/DataChannel, 위치 공유, 상담자 처리 API, AI 좌표의 지도 anchor 매핑은 MVP 완성을 위해 남아 있다.

## 1. 프로젝트 개요

### 1.1 서비스명

서비스명: **PinGo**

### 1.2 서비스 한 줄 소개

외국인 관광객이 지하철역 내부에서 현재 위치를 인식하고, 목적지 또는 역 주변 장소까지 길을 안내받으며, 문제가 발생하면 해당 역의 역무원과 실시간 상담으로 도움받을 수 있는 실내 이동 지원 서비스이다.

### 1.3 서비스 핵심 개념

본 서비스는 단순한 지하철 노선 안내 또는 외부 지도 서비스가 아니다.

기존 지도 서비스가 약한 **지하철역 내부 이동 문제**를 해결하기 위해, 카메라 기반 위치 인식, 실내 지도, 경로 탐색, 외부 지도 앱 연계, WebRTC 상담을 하나의 흐름으로 연결한다.

사용자는 출구 번호를 몰라도 역 주변 장소를 선택할 수 있고, 서비스는 해당 장소와 가까운 출구를 추천한 뒤 현재 위치에서 출구까지 실내 경로를 안내한다. 출구에 도착하면 Kakao Map으로 목적지까지의 길찾기를 이어간다.

## 2. 기획 배경

### 2.1 문제 상황

외국인 관광객은 한국 지하철을 이용할 때 다음과 같은 어려움을 겪는다.

- 지하철역 내부 구조가 복잡해 현재 위치를 파악하기 어렵다.
- 지하철역 안에서는 GPS 정확도가 낮아 일반 지도 앱만으로 길을 찾기 어렵다.
- 출구 번호, 노선 방향, 환승 통로, 개찰구 안팎 구분이 익숙하지 않다.
- 한국어 안내판을 이해하기 어렵거나, 안내판을 보고도 어느 방향으로 가야 하는지 판단하기 어렵다.
- 큰 짐, 휠체어, 유모차를 이용하는 경우 계단 없는 경로를 찾기 어렵다.
- 교통카드, 발매기, 개찰구 문제 발생 시 즉시 도움을 받기 어렵다.
- 목적지가 역 주변 장소일 경우 어느 출구로 나가야 하는지 알기 어렵다.

### 2.2 기존 서비스의 한계

네이버지도, 카카오지도, 구글지도 등 기존 지도 서비스는 역 밖의 경로 안내에는 강점이 있지만, 지하철역 내부의 세밀한 이동 안내에는 한계가 있다.

- 실내에서 GPS 기반 현재 위치 확인이 어렵다.
- 역 내부의 층, 통로, 개찰구, 승강장 위치를 정확히 안내하기 어렵다.
- 출구까지 이동하는 실제 실내 경로를 단계적으로 안내하기 어렵다.
- 외국인 관광객의 언어 문제와 현장 문제를 동시에 해결하기 어렵다.
- 자동 안내가 실패했을 때 사람이 이어받는 구조가 부족하다.

### 2.3 기획 의도

본 서비스는 외국인 관광객이 지하철역 내부에서 겪는 길찾기 문제를 해결하기 위해 기획되었다.

특히 다음 세 가지 문제를 중점적으로 해결한다.

1. **현재 위치를 모르는 문제**
   - 카메라 기반 VPS 또는 보조 위치 인식을 통해 사용자의 실내 위치를 확인한다.

2. **출구와 목적지를 연결하지 못하는 문제**
   - 사용자가 역 주변 장소를 선택하면 적절한 출구를 자동으로 추천하고, 그 출구까지 실내 길찾기를 제공한다.

3. **자동 안내만으로 해결되지 않는 문제**
   - WebRTC 기반 실시간 상담을 통해 해당 역의 역무원 또는 상담자가 사용자를 지원한다.

## 3. 서비스 목표

### 3.1 최종 목표

외국인 관광객이 지하철역 안에서 길을 잃지 않고, 목적지까지 이어지는 이동 흐름을 스스로 완료할 수 있도록 지원한다.

### 3.2 MVP 목표

MVP는 서울 전체 지하철역을 대상으로 하지 않고, **1개의 대표 역사**에서 핵심 사용자 경험을 검증하는 것을 목표로 한다.

MVP에서 검증할 핵심 흐름은 다음과 같다.

```text
서비스 접속
→ 언어 선택
→ 현재 역 확인
→ 출발지 및 목적지 선택
→ 현재 위치 인식
→ 출구 또는 시설까지 실내 경로 안내
→ 출구 도착 시 외부 지도 앱 연계
→ 문제 발생 시 WebRTC 상담 연결
```

### 3.3 기술 검증 목표

- 스마트폰으로 촬영한 지하철역 내부 영상을 프레임 이미지로 변환한다.
- COLMAP을 활용해 대상 역사 일부 구간의 3D Map 구축을 시도한다.
- 자체 구축 VPS로 주요 지점의 위치 인식 가능성을 검증한다.
- 자체 VPS 정확도 또는 안정성이 부족한 경우 Multiset AI 등 외부 VPS 솔루션 또는 QR/마커 기반 보조 인식으로 시연 안정성을 확보한다.
- WebRTC를 통해 사용자와 역무원 화면 간 영상·음성 상담 흐름을 구현한다.

### 3.4 서비스 제공 형태

서비스는 별도 설치가 필요한 네이티브 앱이 아니라 **웹앱** 형태로 제공한다.

외국인 관광객은 여행 중 새로운 앱을 설치하는 데 부담을 느낄 수 있으므로, QR 코드, 링크, 검색 등을 통해 웹에 접속한 뒤 바로 서비스를 사용할 수 있도록 한다.

사용자는 별도 로그인을 하지 않고 서비스를 이용한다. 로그인은 상담자 또는 관리자에게만 요구하며, 상담자는 로그인 후 일반 사용자 화면이 아닌 상담자 전용 페이지로 이동한다.

## 4. 목표 사용자

### 4.1 주요 사용자

#### 외국인 관광객

한국 지하철 이용 경험이 부족하고, 역 내부 구조나 출구 번호 체계에 익숙하지 않은 사용자이다.

주요 요구는 다음과 같다.

- 현재 위치를 알고 싶다.
- 목적지와 가까운 출구를 알고 싶다.
- 출구까지 실제로 어떻게 이동해야 하는지 알고 싶다.
- 한국어를 몰라도 길을 찾고 싶다.
- 문제가 생겼을 때 역무원에게 도움을 받고 싶다.

#### 동행 사용자

같은 역 안에서 친구, 가족, 일행을 만나야 하는 사용자이다.

주요 요구는 다음과 같다.

- 내 위치를 다른 사람에게 공유하고 싶다.
- 상대방이 공유한 위치까지 찾아가고 싶다.
- 복잡한 역 안에서 만나는 장소를 쉽게 정하고 싶다.

#### 역무원 또는 상담자

역 내부에서 어려움을 겪는 외국인 관광객을 원격으로 도와주는 사용자이다.

주요 요구는 다음과 같다.

- 사용자가 어느 역에 있는지 확인하고 싶다.
- 사용자의 카메라 화면을 보고 현재 상황을 파악하고 싶다.
- 사용자 화면에 방향 표시 또는 목적지를 지정하고 싶다.
- 사용자가 이해할 수 있는 방식으로 간단히 안내하고 싶다.

#### 서비스 관리자

역 지도, 경로, 시설, VPS 데이터, 상담자 정보를 관리하는 사용자이다.

주요 요구는 다음과 같다.

- 역 내부 지도와 시설 정보를 등록하고 수정하고 싶다.
- 경로 노드와 간선 정보를 관리하고 싶다.
- VPS 기준 데이터와 인식 실패 데이터를 관리하고 싶다.
- 역무원 또는 상담자 계정을 관리하고 싶다.

## 5. 핵심 사용자 문제와 해결 방식

| 사용자 문제 | 해결 방식 |
| --- | --- |
| 실내에서 현재 위치를 알기 어렵다 | 카메라 기반 VPS, QR/마커, 수동 위치 선택 제공 |
| 출구 번호를 모른다 | 역 주변 장소 선택 시 가장 가까운 출구 자동 추천 |
| 역 내부 경로가 복잡하다 | 층별 2D 지도와 단계별 경로 안내 제공 |
| 큰 짐이나 휠체어로 이동하기 어렵다 | 계단 없는 경로, 엘리베이터 중심 경로 제공 |
| 안내판을 읽기 어렵다 | 다국어 UI, 정형화된 안내 문구, 카메라 방향 표시 제공 |
| 자동 안내가 실패한다 | 해당 역 역무원과 WebRTC 상담 연결 |
| 역 밖 목적지까지 이어가기 어렵다 | 출구 도착 후 외부 지도 앱 길찾기 연계 |
| 역 안에서 일행을 만나기 어렵다 | 사용자 간 위치 공유와 공유 위치까지 길찾기 제공 |

## 6. 서비스 핵심 기능

### 6.1 현재 역 확인

사용자의 GPS 위치를 기반으로 주변 지하철역 후보를 표시하고, 사용자가 직접 역을 선택하거나 확인할 수 있도록 한다.

### 6.2 실내 위치 인식

사용자가 카메라로 주변을 비추면 VPS 또는 보조 인식 방식을 통해 현재 위치 후보를 제공한다.

위치 인식 결과는 다음 정보를 포함한다.

- 현재 역
- 현재 층
- 현재 위치
- 바라보는 방향
- 위치 신뢰도

### 6.3 실내 지도

대상 역사 내부의 층별 2D 지도를 제공한다.

지도에는 다음 정보가 표시된다.

- 현재 위치
- 목적지
- 전체 경로
- 주요 시설
- 층간 이동 지점
- 출구
- 개찰구
- 승강장
- 엘리베이터
- 에스컬레이터

### 6.4 목적지 검색

사용자는 역 내부 목적지 또는 역 주변 장소를 검색할 수 있다.

역 내부 목적지 예시는 다음과 같다.

- 특정 출구
- 승강장
- 환승 통로
- 화장실
- 엘리베이터
- 에스컬레이터
- 역무실
- 교통카드 충전기

역 주변 장소 예시는 다음과 같다.

- 관광지
- 호텔
- 음식점
- 쇼핑몰
- 공연장
- 공항버스 정류장
- 랜드마크

### 6.5 출구 자동 매칭

사용자가 역 주변 장소를 선택하면 서비스는 해당 장소와 가장 가까운 출구를 추천한다.

예시는 다음과 같다.

```text
목적지: 코엑스몰
추천 출구: 삼성역 5번 출구
실내 목적지: 5번 출구
외부 목적지: 코엑스몰
```

### 6.6 실내 경로 탐색

현재 위치에서 목적지까지 이동 가능한 경로를 생성한다.

MVP에서는 다음 3가지 경로 옵션을 우선 지원한다.

- 빠른 경로: 모든 이동 수단을 허용하고 가장 빠른 경로를 제공한다.
- 계단 없는 경로: 계단을 제외하고 에스컬레이터와 엘리베이터는 허용한다.
- 엘리베이터 중심 경로: 계단과 에스컬레이터를 제외하고 평지와 엘리베이터 중심으로 안내한다.

### 6.7 이동 안내

사용자가 실제로 이동할 수 있도록 다음 방식으로 안내한다.

- 2D 지도 기반 경로 표시
- 단계별 안내 문장
- 카메라 화면 위 방향 화살표
- 주요 지점 재인식
- 음성 안내

### 6.8 외부 지도 앱 연계

사용자가 출구에 도착하면 외부 지도 앱으로 목적지까지 길찾기를 이어갈 수 있도록 한다.

MVP 우선 연계 대상은 다음과 같다.

- Kakao Map

앱 자동 실행보다 사용자가 선택할 수 있는 링크 또는 버튼 제공을 기본 방식으로 한다. 추후 여유가 있을 경우 카카오지도 또는 구글지도 연계도 추가 검토한다.

### 6.9 WebRTC 역무원 상담

사용자가 길찾기, 개찰구, 발매기, 교통카드 문제 등으로 어려움을 겪을 경우 WebRTC 상담을 요청할 수 있다.

상담 요청 시 사용자의 현재 역 정보가 상담자 또는 역무원에게 전달된다.

사용자 앱은 비로그인 기반으로 동작하며, 상담자만 로그인한다. 상담자는 로그인 후 상담자 전용 페이지에서 해당 역의 상담 요청 목록을 확인하고 상담을 수락한다.

상담자는 다음 기능을 사용할 수 있다.

- 사용자 영상 확인
- 음성 상담
- 사용자 목적지 확인
- 지도 위 시설 또는 목적지 지정
- 사용자 화면에 화살표 표시
- 경로 갱신 요청

### 6.10 사용자 간 위치 공유

사용자는 자신의 현재 위치를 공유 링크 또는 코드로 전달할 수 있다.

다른 사용자는 공유된 위치를 목적지로 설정하고, 자신의 현재 위치에서 해당 위치까지 실내 경로 안내를 받을 수 있다.

사용자 간 위치 공유는 최종 역할분배 기준에서 필수 기능 요구사항으로 포함한다.

### 6.11 교통카드 간단 추천

사용자의 여행 기간, 방문 지역, 하루 이동 횟수를 바탕으로 적합한 교통카드 유형을 간단 추천한다.

교통카드 간단 추천은 최종 역할분배 기준에서 필수 기능 요구사항으로 포함한다.

추천 대상 예시는 다음과 같다.

- 일반 Tmoney
- 기후동행카드
- 1일권
- 2일권
- 일회용 승차권

## 7. MVP 범위

### 7.1 MVP 전제

- 대상 역사는 1개로 제한한다.
- 대상 역사 전체가 아니라 시연에 필요한 주요 동선을 우선 구축한다.
- VPS는 COLMAP 기반 자체 구축을 우선 시도한다.
- 자체 VPS가 불안정할 경우 Multiset AI, QR/마커, 수동 위치 선택 방식으로 보완한다.
- 교통카드 추천과 사용자 간 위치 공유는 최종 기능 요구사항 32개에 포함해 필수 범위로 구현한다.
- 서비스는 웹앱 형태로 제공하며, 사용자는 비로그인으로 이용한다.
- 상담자와 관리자는 로그인을 통해 전용 페이지에 접근한다.

### 7.2 MVP 대상 역

MVP 대상 역은 **역삼역**으로 확정한다.

역삼역을 기준으로 촬영 가능 구간, 지도 구축 난이도, 대표 외부 목적지 연계를 검증한다. 다른 역 지원은 8월 9일 이후 확장 백로그로 관리한다.

### 7.3 대표 시연 동선

대표 시연 동선은 가능하다면 다음 흐름으로 구성한다.

```text
사용자가 지하철에서 내린 직후
→ 승강장 또는 개찰구 근처에서 현재 위치 인식
→ 역 주변 관광지 또는 주요 장소 선택
→ 해당 장소와 가까운 출구 자동 추천
→ 현재 위치에서 출구까지 실내 길찾기
→ 출구 도착
→ Kakao Map 길찾기로 외부 이동 이어가기
```

실제 시연 동선은 대상 역이 확정된 후, 촬영 가능 구간과 지도 구축 난이도를 고려해 구체화한다.

## 8. 대표 사용자 시나리오

### 8.1 역 주변 장소로 이동하는 외국인 관광객

```text
사용자가 서비스에 접속한다.
→ 언어를 영어로 선택한다.
→ GPS 기반으로 현재 역을 확인한다.
→ 목적지로 역 주변 장소를 검색한다.
→ 서비스가 가장 가까운 출구를 추천한다.
→ 사용자가 카메라로 현재 위치를 인식한다.
→ 서비스가 현재 위치에서 출구까지 실내 경로를 안내한다.
→ 사용자가 출구에 도착한다.
→ 서비스가 외부 지도 앱 길찾기 링크를 제공한다.
```

### 8.2 출구 번호를 모르는 사용자

```text
사용자가 호텔 이름을 검색한다.
→ 서비스가 호텔과 가까운 출구를 찾는다.
→ 해당 출구를 실내 목적지로 설정한다.
→ 사용자의 현재 위치에서 출구까지 경로를 안내한다.
```

### 8.3 위치 인식 실패 사용자

```text
사용자가 카메라로 주변을 비춘다.
→ VPS 신뢰도가 낮게 표시된다.
→ 서비스가 재촬영을 요청한다.
→ 그래도 실패하면 주변 랜드마크 후보를 보여준다.
→ 사용자가 지도에서 현재 위치를 직접 선택한다.
→ 선택된 위치를 기준으로 경로를 다시 생성한다.
```

### 8.4 역무원 상담 요청 사용자

```text
사용자가 상담 요청 버튼을 누른다.
→ 현재 역 정보와 문제 유형이 상담자에게 전달된다.
→ 해당 역 역무원이 상담을 수락한다.
→ 사용자가 카메라 영상을 공유한다.
→ 역무원이 지도 위 목적지 또는 시설을 지정한다.
→ 사용자 앱의 경로가 갱신된다.
```

### 8.5 역 안에서 친구를 만나는 사용자

```text
사용자 A가 자신의 현재 위치를 공유한다.
→ 사용자 B가 공유 링크로 접속한다.
→ B의 현재 위치를 인식한다.
→ A의 위치를 목적지로 설정한다.
→ B에게 A까지의 실내 경로를 안내한다.
```

## 9. 서비스 차별점

### 9.1 기존 지도 앱과의 차별점

| 기존 지도 앱 | 본 서비스 |
| --- | --- |
| 역 밖 길찾기에 강함 | 역 내부 길찾기에 집중 |
| 실내 GPS 정확도 한계 | 카메라 기반 VPS와 보조 위치 인식 활용 |
| 출구 번호를 알아야 검색이 쉬움 | 장소명만 입력해도 출구 추천 |
| 자동 안내 중심 | 실패 시 역무원 상담 연결 |
| 외국인 특화 안내 부족 | 다국어 UI와 역무원에게 보여줄 문장 제공 |

### 9.2 기술적 차별점

- COLMAP 기반 자체 VPS 구축 시도
- 외부 VPS 솔루션을 보완 전략으로 활용
- 실내 지도와 카메라 방향 안내 결합
- WebRTC DataChannel을 활용한 상담자-사용자 화면 동기화
- 출구 이후 외부 지도 앱으로 길찾기 흐름 연결

### 9.3 사용자 경험 차별점

- 사용자는 출구 번호를 몰라도 된다.
- 목적지를 장소명으로 검색하면 출구까지 안내받을 수 있다.
- 길을 잃었을 때 앱 안에서 바로 역무원 도움을 받을 수 있다.
- 같은 역 안에서 일행의 위치까지 길찾기가 가능하다.

## 10. 성공 기준

### 10.1 사용자 경험 성공 기준

- 사용자가 별도 앱 설치 없이 웹앱에 접속해 서비스를 시작할 수 있다.
- 사용자가 1개 대상 역사에서 현재 위치를 확인할 수 있다.
- 사용자가 역 내부 목적지 또는 역 주변 장소를 선택할 수 있다.
- 사용자가 추천된 출구까지 실내 경로 안내를 받을 수 있다.
- 출구 도착 후 외부 지도 앱으로 길찾기를 이어갈 수 있다.
- 위치 인식 실패 시 대체 흐름을 통해 안내를 계속할 수 있다.
- 사용자가 WebRTC 상담을 요청하고 상담자와 연결될 수 있다.

### 10.2 기술 성공 기준

- 대상 역사 주요 지점에 대한 VPS 또는 보조 위치 인식이 동작한다.
- COLMAP 기반 3D Map 구축 결과를 산출한다.
- 2D 지도 기반 경로 탐색이 동작한다.
- WebRTC 영상 또는 음성 연결이 동작한다.
- 상담자가 로그인 후 상담자 전용 페이지에서 상담 요청을 확인할 수 있다.
- 상담자가 지정한 목적지 또는 시설이 사용자 앱에 반영된다.

### 10.3 시연 성공 기준

다음 흐름을 끊기지 않고 시연할 수 있으면 MVP 성공으로 판단한다.

```text
현재 역 선택
→ 현재 위치 인식
→ 역 주변 장소 선택
→ 출구 자동 추천
→ 실내 경로 안내
→ 출구 도착
→ 외부 지도 앱 연계
→ 문제 상황에서 WebRTC 상담 연결
```
